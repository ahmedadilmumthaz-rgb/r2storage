# API Reference

Two API surfaces:

- **S3-compatible API** — the primary way to upload/download/manage objects. Uses AWS **SigV4** authentication and returns S3-style XML. Works with the AWS CLI, boto3, `@aws-sdk/client-s3`, Rclone, Cyberduck, etc.
- **Admin REST API** — JSON endpoints locked behind the `ADMIN_SECRET` header, for managing buckets, access keys, custom domains, and analytics from the control panel.

Base URLs (examples use `http://YOUR_VPS_IP:4000`; in production you normally reach everything through `https://your-cdn-domain`):

```
S3:     http://YOUR_VPS_IP:4000/s3
Admin:  http://YOUR_VPS_IP:4000/api/admin
```

---

## 1. Authentication

### 1.1 S3-compatible API

There are three accepted credential styles, in this order:

1. **SigV4 Authorization header** (`Authorization: AWS4-HMAC-SHA256 ...`) — what AWS SDKs, the AWS CLI, boto3, Rclone, Cyberduck emit. **Region: `us-east-1`, Service: `s3`.**
2. **Presigned URL** (`X-Amz-Algorithm`, `X-Amz-Credential`, `X-Amz-Signature`, ...) — generated by the admin API or by SDK presigners.
3. **Convenience headers** — for simple internal tools/scripts. Both credentials are required:
   - `x-access-key-id: <accessKeyId>` + `x-access-key-secret: <secretAccessKey>` → that key's permissions.
   - `x-api-key: <secretAccessKey>` → full access, looked up by secret.
   An **Access Key ID alone is not a credential** (it appears in presigned URLs and the dashboard) and is rejected.

Access keys come from the control panel → **Access Keys**. Every key has a **permission** (`FULL` / `READ_ONLY` / `WRITE_ONLY`) and an optional **bucketFilter**. All read/write operations enforce both.

### 1.2 Admin API

Every `/api/admin/*` request must be authenticated **one of two ways**:

**A. Session cookie (dashboard).** `POST /api/admin/login` with the secret exchanges it for an `HttpOnly; SameSite=Strict` cookie; subsequent requests carry the cookie automatically:

```bash
# login -> sets the r2_admin_sid cookie
curl -c cookies.txt -X POST -H "Content-Type: application/json" \
     -d '{"secret":"<your ADMIN_SECRET>"}' \
     https://panel.example.com/api/admin/login

# with TOTP 2FA enabled (ADMIN_TOTP_SECRET), include the 6-digit code:
curl -c cookies.txt -X POST -H "Content-Type: application/json" \
     -d '{"secret":"<your ADMIN_SECRET>","totp":"123456"}' \
     https://panel.example.com/api/admin/login

# authenticated requests
curl -b cookies.txt https://panel.example.com/api/admin/overview

# log out (revokes the session server-side)
curl -b cookies.txt -X POST https://panel.example.com/api/admin/logout

# check login state
curl https://panel.example.com/api/admin/session   # {"authenticated":true|false}
```

Wrong-secret logins are rate-limited (10/min/IP on `/api/admin/login`) **and** counted toward an escalating lockout: a source IP is blocked for `LOGIN_IP_COOLDOWN_SEC` (default 30 min) after `LOGIN_FAIL_THRESHOLD` (default 5) consecutive failures; once `LOGIN_GLOBAL_THRESHOLD` (default 15) failures accumulate across all IPs, a global cooldown kicks in that doubles each time it re-triggers (cap 1 hour). Locked-out logins return `429` with a `Retry-After` header. The `GET /api/admin/overview` `failedLogins24h` field reports how many failures were recorded in the last 24h. When `ADMIN_TOTP_SECRET` is set, the login must also carry a valid `totp` field (6-digit RFC 6238 code); a missing/wrong code fails exactly like a wrong secret (same lockout + delay). The `x-admin-secret` header authenticates scripts without 2FA.

**B. `X-Admin-Secret` header (scripts/CLI).** Kept for tooling:

```
X-Admin-Secret: <your ADMIN_SECRET>
```

A wrong or missing credential returns `401 {"error": "Unauthorized..."}`. Sessions expire after `ADMIN_SESSION_TTL_HOURS` of inactivity (default 24h) and are **sliding-renewed** on each authenticated request — but never past the absolute `ADMIN_SESSION_MAX_HOURS` ceiling (default 7 days), so even a session kept alive by a polling dashboard eventually dies. `GET /api/admin/session` reports `{"authenticated": bool, "expiresAt": ISO|null}`.

If `ADMIN_ALLOWED_CIDRS` is set (comma-separated IPv4/IPv6 CIDRs), the entire admin API — **login included** — returns `403` from any client IP outside those networks, checked before auth so outsiders can't even start a session. Behind nginx the client IP is `CF-Connecting-IP`.

## 2. S3-compatible operations

Endpoint pattern (path-style addressing — always include `/s3`):

```
GET|PUT|HEAD|POST|DELETE  /s3/<bucket>[/<key>][?query]
```

### 2.1 Operations table

| Operation | Method + path | Auth | Notes |
| --- | --- | --- | --- |
| ListObjectsV1 + V2 | `GET /s3/<bucket>?prefix=<p>` (V1: `marker=`; V2: `list-type=2&continuation-token=`/`start-after=`) | public buckets: none; private: read | XML `<ListBucketResult>`; up to 1000 keys; `delimiter=` folds into `<CommonPrefixes>`; `encoding-type=url` URL-encodes keys; both dialects paginate (V1 `NextMarker`, V2 `NextContinuationToken`) |
| PutObject | `PUT /s3/<bucket>/<key>` | write | body is streamed to disk; returns `ETag` header; supports conditional writes (below) |
| GetObject | `GET /s3/<bucket>/<key>` | public: none; private: read | streams body; sets `Content-Type`, `ETag`, `Content-Length`; supports **byte-range + conditional GET** (below) |
| HeadObject | `HEAD /s3/<bucket>/<key>` | public: none; private: read | headers only, no body |
| DeleteObject | `DELETE /s3/<bucket>/<key>` | **full** | `204` |
| DeleteObjects | `POST /s3/<bucket>?delete` | **full** | XML body `<Delete><Object><Key>k</Key></Object>...<Quiet>true</Quiet></Delete>` (≤ 1000 keys); returns `<DeleteResult>` echoing deleted keys unless `<Quiet>true</Quiet>`. Missing keys are silently ignored; body capped at 1MB (413). |
| CopyObject | `PUT /s3/<bucket>/<key>` + `x-amz-copy-source: /<src-bucket>/<src-key>` | write (dest) + read (src) | server-side copy (no payload); returns `CopyObjectResult` XML. `x-amz-metadata-directive: COPY` (default) carries the source's `Content-Type`; `REPLACE` takes the request's `Content-Type`. Copying an object onto itself requires `REPLACE` (else `400`). Honors the same conditional-write headers as PutObject on the destination. |
| CreateMultipartUpload | `POST /s3/<bucket>/<key>?uploads` | write | XML with `<UploadId>` |
| ListMultipartUploads | `GET /s3/<bucket>?uploads` | read | XML `<ListMultipartUploadsResult>`; paginates with `key-marker`/`upload-id-marker` (resumes after that (key, uploadId) pair; a bare `key-marker` skips the whole key), capped by `max-uploads`, filtered by `prefix`, folds `delimiter` into `<CommonPrefixes>`, honors `encoding-type=url`. Uploads ordered by (key, uploadId) so markers resume deterministically. |
| ListParts | `GET /s3/<bucket>/<key>?uploadId=<id>` | read | XML `<ListPartsResult>` of uploaded parts (`<PartNumber>`, `<ETag>`, `<Size>`, `<LastModified>`); paginates with `part-number-marker`/`max-parts`. The `uploadId` must belong to this bucket and key, else `404 NoSuchUpload`. |
| UploadPart | `PUT /s3/<bucket>/<key>?uploadId=<id>&partNumber=<n>` | write | returns `ETag` header |
| CompleteMultipartUpload | `POST /s3/<bucket>/<key>?uploadId=<id>` | write | XML body `<CompleteMultipartUpload>`; returns XML result. Body capped at 1MB (413) — it's only a part list. Honors the same conditional-write headers as PutObject. |
| AbortMultipartUpload | `DELETE /s3/<bucket>/<key>?uploadId=<id>` | write | `204` |
| GetBucketLifecycle | `GET /s3/<bucket>?lifecycle` | read | XML `<LifecycleConfiguration>` of prefix rules (`<ID>`, `<Filter><Prefix>`, `<Status>`, `<Expiration>` `<Days>` or `<Date>`); `404 NoSuchLifecycleConfiguration` when none set. XML parsed by regex — no XML parser (no XXE). |
| PutBucketLifecycle | `PUT /s3/<bucket>?lifecycle` | write | body is the `<LifecycleConfiguration>` XML (capped at 1MB, 413; `Content-MD5` verified when supplied); up to 1000 rules; `<Days>` (≥1) XOR `<Date>` (ISO calendar date); malformed/invalid XML → `400 MalformedXML`. |
| DeleteBucketLifecycle | `DELETE /s3/<bucket>?lifecycle` | write | clears the configuration, `204` |
| Bucket-level PUT/DELETE (other) | `PUT`/`DELETE /s3/<bucket>` | write | only the `?lifecycle` subresource is supported; anything else → `400 InvalidRequest` |

### 2.2 Response conventions

- Success bodies are S3-style XML for list/multipart operations; object GET streams raw bytes.
- Errors are S3-style XML:
  ```xml
  <Error><Code>NoSuchKey</Code><Message>The specified key does not exist.</Message></Error>
  ```
- Common codes: `AccessDenied` (403), `NoSuchBucket` / `NoSuchKey` (404), `NoSuchUpload` (404), `InvalidPart` / `InvalidPartOrder` (400), `InvalidRequest` (400), `PreconditionFailed` (412), `ConditionalRequestConflict` (409).

### 2.3 Range + conditional GET

`GetObject` (and the custom-domain public route, `https://cdn.<domain>/<key>`) honors S3-compatible byte ranges and HTTP validators:

| Header | Behavior |
|---|---|
| `Range: bytes=0-99` / `bytes=100-` / `bytes=-500` | `206 Partial Content` with `Content-Range: bytes <start>-<end>/<size>`. A single range only; malformed or multi-range requests fall back to `200` with the full object. |
| Unsatisfiable range (start ≥ size, or size 0) | `416 Range Not Satisfiable` with `Content-Range: bytes */<size>` and `<Code>InvalidRange</Code>` |
| `If-None-Match: <etag>` (or `*`) | `304 Not Modified` (also honors weak `W/` and bare tags). Takes precedence over `If-Modified-Since`. |
| `If-Modified-Since: <http-date>` | `304 Not Modified` when the object hasn't been modified since (second granularity) |

`ETag` values are quoted MD5-of-plaintext (e.g. `"9c2e4d5f..."`); `Accept-Ranges: bytes` is advertised on object GETs. Range reads of encrypted blobs decrypt in full then slice (whole-file GCM can't seek), so ranged requests on huge encrypted objects are CPU-bound.

### 2.4 Conditional writes

`PutObject` and `CompleteMultipartUpload` accept S3-style conditional-write headers, evaluated against the current object **before** the body is streamed — a failed precondition never consumes the payload:

| Header | Object state | Result |
|---|---|---|
| `If-Match: "<etag>"` (or `*`, or a comma list) | ETag doesn't match current (or object missing) | `412 PreconditionFailed` |
| `If-Unmodified-Since: <http-date>` | Modified after the date | `412 PreconditionFailed` (a missing object always passes) |
| `If-None-Match: *` | Object already exists | `409 ConditionalRequestConflict` |

`If-Match` takes precedence over `If-Unmodified-Since`. On success the write proceeds normally (object replaced/created).

### 2.5 Public vs private buckets

- **Public bucket**: list/GET/HEAD need no auth; writes and deletes still require a valid key.
- **Private bucket**: everything requires auth. Signed-out `GET` returns `403 AccessDenied`.

## 3. Quick-start samples

### 3.1 AWS CLI

```bash
# configure (keys come from the control panel)
aws configure set aws_access_key_id r2_...
aws configure set aws_secret_access_key ...
aws configure set region us-east-1

ENDPOINT="--endpoint-url http://YOUR_VPS_IP:4000/s3"

# upload / download / list / delete / copy
aws s3 cp logo.png   s3://assets/logo.png  $ENDPOINT
aws s3 cp s3://assets/logo.png ./logo.png  $ENDPOINT
aws s3 ls  s3://assets --recursive         $ENDPOINT
aws s3 rm  s3://assets/old.png             $ENDPOINT
aws s3 sync ./build s3://assets/build      $ENDPOINT

# large files automatically use multipart uploads
aws s3 cp big-file.iso s3://assets/        $ENDPOINT

# presign a download (valid 1 hour)
aws s3 presign s3://assets/logo.png --expires-in 3600 $ENDPOINT
```

### 3.2 Node.js — `@aws-sdk/client-s3`

```bash
npm i @aws-sdk/client-s3 @aws-sdk/s3-request-presigner @aws-sdk/signature-v4-crt
```

```ts
import { S3Client, PutObjectCommand, GetObjectCommand, ListObjectsV2Command, DeleteObjectCommand } from '@aws-sdk/client-s3';
import { getSignedUrl } from '@aws-sdk/s3-request-presigner';

const s3 = new S3Client({
  region: 'us-east-1',
  endpoint: 'http://YOUR_VPS_IP:4000/s3',   // note the /s3 path
  forcePathStyle: true,                      // REQUIRED: path-style addressing
  credentials: {
    accessKeyId: 'r2_...',
    secretAccessKey: '...',
  },
});

// Upload (Buffer / stream / string)
await s3.send(new PutObjectCommand({
  Bucket: 'assets',
  Key: 'uploads/logo.png',
  Body: fs.readFileSync('logo.png'),
  ContentType: 'image/png',
}));

// Download
const res = await s3.send(new GetObjectCommand({ Bucket: 'assets', Key: 'uploads/logo.png' }));
fs.writeFileSync('out.png', Buffer.from(await res.Body.transformToByteArray()));

// List
const list = await s3.send(new ListObjectsV2Command({ Bucket: 'assets', Prefix: 'uploads/' }));
for (const o of list.Contents ?? []) console.log(o.Key, o.Size);

// Delete
await s3.send(new DeleteObjectCommand({ Bucket: 'assets', Key: 'uploads/logo.png' }));

// Presigned download URL (1 hour) — install @aws-sdk/s3-request-presigner
const url = await getSignedUrl(s3, new GetObjectCommand({ Bucket: 'assets', Key: 'uploads/logo.png' }), { expiresIn: 3600 });
console.log(url);
```

Multipart for huge files:

```ts
import { CreateMultipartUploadCommand, UploadPartCommand, CompleteMultipartUploadCommand } from '@aws-sdk/client-s3';

const bucket = 'assets', key = 'huge.iso';
const created = await s3.send(new CreateMultipartUploadCommand({ Bucket: bucket, Key: key }));
const uploadId = created.UploadId!;

const parts: { PartNumber: number; ETag: string }[] = [];
const CHUNK = 5 * 1024 * 1024;                       // 5 MiB per part
const fd = fs.openSync('huge.iso', 'r');
const stat = fs.fstatSync(fd);

for (let i = 0, part = 1; i < stat.size; part++, i += CHUNK) {
  const len = Math.min(CHUNK, stat.size - i);
  const buf = Buffer.alloc(len);
  fs.readSync(fd, buf, 0, len, i);
  const up = await s3.send(new UploadPartCommand({ Bucket: bucket, Key: key, UploadId: uploadId, PartNumber: part, Body: buf }));
  parts.push({ PartNumber: part, ETag: up.ETag! });
}

await s3.send(new CompleteMultipartUploadCommand({
  Bucket: bucket, Key: key, UploadId: uploadId,
  MultipartUpload: { Parts: parts },
}));
```

### 3.3 Python — boto3

```bash
pip install boto3
```

```python
import boto3

s3 = boto3.client(
    "s3",
    endpoint_url="http://YOUR_VPS_IP:4000/s3",
    region_name="us-east-1",
    aws_access_key_id="r2_...",
    aws_secret_access_key="...",
    config=boto3.session.Config(
        s3={"addressing_style": "path"},
        signature_version="s3v4",   # REQUIRED: SigV4 so presigned URLs work
    ),
)

# Upload / download
s3.upload_file("logo.png", "assets", "uploads/logo.png")
s3.download_file("assets", "uploads/logo.png", "out.png")

# Upload a file-like object with a content type
s3.put_object(Bucket="assets", Key="hello.txt", Body=b"hello", ContentType="text/plain")

# List
for obj in s3.list_objects_v2(Bucket="assets", Prefix="uploads/").get("Contents", []):
    print(obj["Key"], obj["Size"])

# Delete
s3.delete_object(Bucket="assets", Key="uploads/logo.png")

# Presigned URL (uses SigV4 — requires signature_version="s3v4" in the client config)
url = s3.generate_presigned_url(
    "get_object",
    Params={"Bucket": "assets", "Key": "uploads/logo.png"},
    ExpiresIn=3600,
)

# Large file: auto multipart
s3.upload_file("huge.iso", "assets", "huge.iso")

# Stream a download to disk
s3.download_fileobj("assets", "huge.iso", open("out.iso", "wb"))
```

### 3.4 Go — `aws-sdk-go-v2`

```go
package main

import (
    "context"
    "fmt"
    "os"
    "github.com/aws/aws-sdk-go-v2/aws"
    "github.com/aws/aws-sdk-go-v2/config"
    "github.com/aws/aws-sdk-go-v2/service/s3"
)

func main() {
    cfg, _ := config.LoadDefaultConfig(context.Background(),
        config.WithRegion("us-east-1"),
        config.WithCredentialsProvider(aws.NewStaticCredentialsProvider("r2_...", "...", "")),
    )
    s3c := s3.NewFromConfig(cfg, func(o *s3.Options) {
        o.BaseEndpoint = aws.String("http://YOUR_VPS_IP:4000/s3")
        o.UsePathStyle = true // required
    })

    f, _ := os.Open("logo.png")
    _, _ = s3c.PutObject(context.Background(), &s3.PutObjectInput{
        Bucket: aws.String("assets"), Key: aws.String("uploads/logo.png"), Body: f,
    })
    fmt.Println("uploaded")
}
```

## 4. Public access via custom domains (no auth needed)

Once a bucket is **Public** and a custom domain is mapped in the control panel (see `DEPLOYMENT.md` § 6–7), anyone can fetch objects directly:

```bash
curl https://cdn.ahmedadil.me/uploads/logo.png -o logo.png
# or the subdomain style
curl https://assets.ahmedadil.me/logo.png -o logo.png
```

These URLs are ideal for `<img>` tags, `<script src>`, CSS, and direct downloads. Responses include `Access-Control-Allow-Origin` (the bucket's `corsOrigins`), `Cache-Control: public, max-age=31536000`, `ETag`, and `Content-Type`.

## 5. Presigned URLs

Presigned URLs grant **temporary, authenticated** access to private objects without exposing the secret key. The admin API creates them; it signs a `GET /s3/<bucket>/<key>` request with the most recent unrestricted access key.

```bash
curl -X POST http://YOUR_VPS_IP:4000/api/admin/buckets/assets/presigned \
  -H "X-Admin-Secret: YOUR_SECRET" \
  -H "Content-Type: application/json" \
  -d '{"key": "uploads/logo.png", "expiresInSeconds": 3600}'
```

```json
{ "url": "http://YOUR_VPS_IP:4000/s3/assets/uploads/logo.png?X-Amz-Algorithm=...&X-Amz-Signature=...", "expiresInSeconds": 3600 }
```

Give the URL to anyone — they can download the object until it expires:

```bash
curl -L "<the-presigned-url>" -o logo.png
```

You can also mint them client-side with the SDKs shown in § 3.2 (`getSignedUrl`), § 3.3 (`generate_presigned_url`), or `aws s3 presign`.

> **boto3 caveat**: the S3 client defaults `generate_presigned_url` to SigV2-style query auth, which this server does not accept. Always configure `signature_version="s3v4"` in the boto3 client (shown in § 3.3). The AWS CLI and `@aws-sdk/client-s3` use SigV4 by default.

## 6. Admin REST API reference

All endpoints require `X-Admin-Secret`. JSON in/out. Errors are `{"error": "..."}` with appropriate status codes.

### 6.1 Overview / analytics

| Method | Path | Description |
| --- | --- | --- |
| GET | `/api/admin/overview` | Bucket/object/key/domain counts, total bytes, last 20 request logs |
| GET | `/api/admin/usage?since=<ISO>` | Usage counters for metering: `{storageBytes, requests, bytesTransferred, since}` — counts are incremental since `since` (omit for all-time). `since` should be the previous poll's response time. |
| GET | `/api/admin/quota` | Current storage quota: `{storageBytesLimit, storageBytes}` (`0` limit = unlimited). |
| PATCH | `/api/admin/quota` | Set `{storageBytesLimit}` (non-negative integer, `0` = unlimited). Writes over quota are rejected with `507`. |

### 6.2 Buckets

| Method | Path | Description |
| --- | --- | --- |
| GET | `/api/admin/buckets` | List buckets with object count + total size |
| POST | `/api/admin/buckets` | Create `{name, isPublic?, corsOrigins?}` — name `[a-z0-9.-]{3,63}` |
| PATCH | `/api/admin/buckets/:name` | Update `{isPublic?, corsOrigins?}` |
| DELETE | `/api/admin/buckets/:name` | Delete bucket + all object blobs on disk |
| GET | `/api/admin/buckets/:name/objects` | List objects in a bucket |
| POST | `/api/admin/buckets/:name/upload` | Upload small file via `multipart/form-data` (`file` field; key = filename) |
| POST | `/api/admin/buckets/:name/presigned` | `{key, expiresInSeconds?}` → `{url}` |
| DELETE | `/api/admin/buckets/:name/objects/*` | Delete one object by key |

### 6.3 Access keys

| Method | Path | Description |
| --- | --- | --- |
| GET | `/api/admin/keys` | List keys |
| POST | `/api/admin/keys` | Create `{name?, permission?, bucketFilter?}` — permission: `FULL`/`READ_ONLY`/`WRITE_ONLY` |
| DELETE | `/api/admin/keys/:id` | Delete a key |

### 6.4 Custom domains

| Method | Path | Description |
| --- | --- | --- |
| GET | `/api/admin/domains` | List mapped domains |
| POST | `/api/admin/domains` | Map `{domain, bucketName}` |
| DELETE | `/api/admin/domains/:id` | Remove mapping |
| GET | `/api/admin/audit?limit=` | Admin audit trail (newest first): `[{actor, ip, userAgent, action, target, detail, createdAt}]`. `actor` = `session` (dashboard), `header` (x-admin-secret script), or `system` (login/logout). `limit` capped at 200 (default 50). Every bucket/key/domain/quota mutation is recorded here along with `login.success`/`logout`. |

### 6.5 Example: full lifecycle with curl

```bash
SECRET="YOUR_ADMIN_SECRET"
API="http://YOUR_VPS_IP:4000/api/admin"

# 1. create a bucket
curl -s -X POST "$API/buckets" -H "X-Admin-Secret: $SECRET" \
  -H "Content-Type: application/json" \
  -d '{"name":"assets","isPublic":true}'

# 2. create a write-only key scoped to that bucket
curl -s -X POST "$API/keys" -H "X-Admin-Secret: $SECRET" \
  -H "Content-Type: application/json" \
  -d '{"name":"uploader","permission":"WRITE_ONLY","bucketFilter":"assets"}'
# -> save accessKeyId + secretAccessKey

# 3. map a custom domain
curl -s -X POST "$API/domains" -H "X-Admin-Secret: $SECRET" \
  -H "Content-Type: application/json" \
  -d '{"domain":"cdn.ahmedadil.me","bucketName":"assets"}'

# 4. upload with that key (WRITE_ONLY: upload works, read is denied)
curl -s -X PUT http://YOUR_VPS_IP:4000/s3/assets/hello.txt \
  -H "x-access-key-id: <accessKeyId>" -H "x-access-key-secret: <secretAccessKey>" --data-binary "hello world"

# 5. presign a temporary download link (admin)
curl -s -X POST "$API/buckets/assets/presigned" -H "X-Admin-Secret: $SECRET" \
  -H "Content-Type: application/json" -d '{"key":"hello.txt","expiresInSeconds":600}'
```

## 7. Common error codes

| HTTP | S3 `<Code>` | Meaning |
| --- | --- | --- |
| 401 | — | Missing/invalid `X-Admin-Secret` (admin API) |
| 403 | `AccessDenied` | Bad signature, expired presigned URL, or permission violation |
| 404 | `NoSuchBucket` / `NoSuchKey` | Bucket or object does not exist |
| 404 | `NoSuchUpload` | `uploadId` unknown (already completed/aborted) |
| 400 | `InvalidPart` / `InvalidPartOrder` | Multipart completion XML doesn't match stored parts/ETags |
| 400 | `InvalidRequest` | Missing required query parameter (e.g. `uploadId`) |
| 409 | — | Bucket name already exists (admin API) |

## 8. Limits & behavior notes

- **Max body**: 10 GB per request (streamed to disk, not buffered in RAM).
- **ListObjects V1 + V2**: up to 1000 keys per page; V2 paginates with `continuation-token` (opaque base64url), V1 with `marker`/`NextMarker`; `encoding-type=url` is honored on both.
- **DeleteObject requires `FULL`** permission (read-only and write-only keys can't delete).
- **Multipart minimum part**: 1 part or more; parts are validated by number + ETag at completion.
- **Signing details**: region `us-east-1`, service `s3`, payload hash `UNSIGNED-PAYLOAD` is accepted; the `host` header must be signed (SDKs/CLI handle this).
- **Admin upload** buffers the file into memory — prefer the S3 `PUT` API for large files.
